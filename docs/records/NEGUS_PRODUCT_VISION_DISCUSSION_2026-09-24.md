## 一页摘要（助手整理）

- **希望成为主工作台：**如果 negus 足够好用，用户希望大家主要使用 negus。
- **桌面是主入口：**进入后看到自己定制或助手推荐的内容，有需求就在桌面与助手交流。
- **桌面总助理：**直接处理轻量快速请求，熟悉关键信息的获取路径；需要时分派工作，或找其他助手回答。
- **核心体验偏好：**用户个人更喜欢前台聊天、后台办事；同时认为自定义业务面板有助于尽快宣传。
- **能力愿景：**自定义 UI/业务面板、多 Agent 共同讨论决策、任务分发及结果可追溯。
- **原始动机仍存在：**让使用中转站的 Codex 用户能在手机继续使用 Codex；但用户担心两套对话管理方式带来割裂。
- **组件生成是待验证猜想：**前端样式与真实数据准备并行，也可能有组件负责人及多级分派；尚不确定效率收益。
- **复用方向：**希望积累用户调整后的最终样式，为后来类似需求提供参考或直接复用；收集、共享和授权方式尚未讨论确定。

## 2. 用户明确表达的产品方向

### 2.1 从手机 Codex 入口发展为 negus 主工作台

最初目标是让使用中转站的 Codex 用户在手机上继续工作。随着设想扩大，用户希望融合 Grok Bot、工作伙伴及 DeepSeek Harness 的部分体验，同时与 Codex 兼容。（原话 05、08）

用户已明确：如果 negus 足够好用，希望用户主要使用 negus。（原话 10）

尚未决定：兼容必须覆盖哪些对象和行为，已有 Codex 对话如何接入，是否以及如何回到 Codex 继续工作。不能据此宣称已决定单向迁移、放弃同步，或保证双向无缝切换。

### 2.2 桌面是用户进入产品后的起点

用户希望桌面展示自己想看到的内容，或助手推荐的内容；有需求直接在桌面与助手对话。（原话 11）

自定义 UI 的例子包括：框选区域后说明所需内容；把原来用来处理财务的 Codex 对话转化为直观的可操作面板；展示项目运营情况，并通过对话询问相关数据。（原话 05）

“任何想看到的东西”是愿景表达，尚未确定组件范围、可操作能力、移动端布局和技术边界。

### 2.3 桌面总助理

用户给出的职责是：

1. 处理轻量、快速的请求。
2. 熟知所有关键信息的路径。
3. 必要时分配任务。
4. 不知道的事情可以找其他助手来回答，参考 Grok Bot。

用户明确表示相关逻辑尚未想好。（原话 14）因此，尚不能规定必须由总助理转述所有回答，也不能规定专员必须直接进入桌面对话。两种呈现方式仍待设计。

### 2.4 多 Agent 讨论与前后台协作

用户希望通过多个 Agent 共同讨论决策，减少偏见；同时希望任务分发让前台助手持续快速响应，后台任务可追溯。（原话 05）

这是体验目标，不是已验证的效果。使用几个 Agent、什么任务需要讨论、如何形成结论、如何控制成本和耗时，都尚未决定。

### 2.5 商业与宣传

用户对目标客户的回答是“愿意给钱的人”，尚未限定职业、团队规模或具体付费场景。用户个人偏好前台聊天加后台办事，同时认为自定义业务面板更利于尽快宣传。（原话 08）

不能将此整理为“已确定先做面板”或“已确定只做 Codex 用户市场”；本轮没有作出这样的优先级承诺。

## 3. 用户提出、尚待验证的组件生成设想

以下来自原话 12，用户明确称其为猜想，并欢迎更优雅高效的方式：

1. 用户在桌面对总助理提出新增组件的需求。
2. 总助理分派两个不同助手并行工作：一个负责前端样式，先用样例数据；另一个寻找真实项目数据。
3. 两者合作，快速形成可用组件。
4. 用户根据需求继续修改。
5. 积累最终样式，以后遇到其他用户的类似需求时优先提供这些样式。

可能存在多级分派：桌面总助理把工作交给专门负责该组件的负责人，组件负责人再继续分配。

**未决定的部分：**两个助手是否固定配置、组件负责人是否长期存在、多级分派何时启用、样例与真实数据如何衔接、用户先看到什么、发布前是否确认、如何判断分工真的提高效率。

跨用户模板收集也是设想，未确定是否默认收集、是否需要用户主动分享、保留哪些信息、如何排除业务数据与处理授权。

## 4. 助手提出的理解与建议（未经用户逐项确认）

本节用于保留讨论上下文，不作为正式产品决定：

- 将 negus 视为主要工作空间，将 Codex 兼容视为接入已有工作的能力；具体兼容承诺需要另行验证。
- 桌面组件可以关联实际数据、负责的 Agent、后台任务和交付结果，避免只生成静态展示。
- 前端和数据并行前先约定字段及含义，并明确标识样例数据。
- 按复杂度决定直接执行、单次委派还是多级分派，不固定为每个组件都创建多个助手。
- 组件负责人可以长期存在，执行助手可以临时创建；这是助手建议，并非用户已确认的角色生命周期。
- 将快速询问信息与需要独立追踪的调查/制作任务区分。
- 分开个人偏好积累与跨用户模板共享，跨用户共享的授权和数据剥离机制需要明确。

助手曾建议收窄为可替换底层 Agent 的业务控制层，后在本次讨论中承认这不足以承载用户对桌面、自定义 UI 和协作体验的愿景。该早期建议不应被后续开发者误当作用户选定路线。
