# Negus 桌面产品需求文档

更新时间：2026-09-22 00:12 +08:00  
关联：FEAT-023  
状态：仅定制模式、画线规整区域及取消撤销入口已确认并实施；内容自定义实现方式、技术分层及其余规划继续讨论。以下未确认的目标不能作为已实现功能清单。最新交互规则见第7、8节，优先于旧案例的按钮与生成流程。

## 1. 产品定位

Negus 桌面是用户可以用自然语言安排、创建和调整的工作空间。用户直接看到工作内容、运行状态和操作结果；助手负责把需求落实到指定位置。

核心体验：框一个地方，说想要什么，那里出现可用的东西。以后点它就能使用，长按就能调整，再说一句就能修改。

对话是指挥入口，不是桌面内容的默认形态。解释、道歉、开发报告不得自动变成桌面卡片。产品价值来自持续使用的业务功能，例如每天审图、查看自动化、访问素材，而不是多放几个聊天窗口。

### 成功标准

- 用户无需理解组件类型、会话编号、网格坐标或代码文件。
- 简单展示需求直接出现结果，不因未指定非必要素材反复追问。
- 用户始终知道正在修改哪里、是否执行成功、如何撤回。
- 撤销内容修改不会导致区域消失；移除组件不会偷偷停止业务任务。
- 数据状态有明确来源，首页正常时只展示工作，故障时提供明确恢复动作。

## 2. 范围与阶段

| 阶段 | 必须交付 | 不计入本阶段完成 |
| --- | --- | --- |
| A：基础桌面闭环 | 区域创建、组件显示、目标对话、长按菜单、拖动缩放、固定、分层撤销、加载恢复、图片与两个任务组件 | 任意业务应用自动生成 |
| B：真实业务组件 | 审图批注、素材目录；新增一种必须打通真实来源、操作与恢复 | 用静态说明替代业务能力 |
| C：跨设备与语音 | 账号下布局同步、响应式布局策略、语音指令与执行反馈 | 未验证硬件型号适配承诺 |

本 PRD 给出完整目标体验，实施逐阶段验收。B/C 未完成时不展示假入口，不声称已经支持。独立区域上下文和可靠执行通道属于 A，不能仅靠 prompt 替代。

## 3. 核心对象与职责

| 对象 | 用户理解 | 负责什么 | 不负责什么 |
| --- | --- | --- | --- |
| 桌面 | 我的工作台 | 组织组件和布局 | 自动运行用户没有授权的业务 |
| 区域 | 我要把东西放在这里 | 稳定位置、尺寸、组件标识 | 展示整段助手回复 |
| 组件 | 这里能做的工作 | 内容呈现、业务交互、数据刷新 | 擅自改变其他组件 |
| 区域对话 | 针对这里提出要求 | 保留该区域需求、修改历史和执行上下文 | 混入别的区域指令 |
| 操作记录 | 刚才改了什么 | 记录目标、前后版本、结果、可否撤销 | 把一切变化当成同一种撤销 |
| 自动化任务 | 后台实际执行的工作 | 周期、执行生命周期、运行记录 | 随桌面组件移除而自动删除 |

一个区域默认承载一个组件；组件内部可以包含列表、筛选、图片等。更换内容或组件保留区域身份。移动或固定不新建对话，不清空业务内容。

## 4. 页面与信息层级

首页保留顶部导航、桌面和既有助手输入入口。手机以紧凑双列卡片为默认，允许用户主动调整为更小或更大的区域。组件不能为了塞入说明、错误按钮而破坏布局。

普通模式以使用为主：滚动、查看、打开组件、操作业务。编辑模式以布局管理为主：选中、拖动、缩放、画框。模式必须有明确入口和退出按钮，退出后不残留拖动状态。

桌面输入框默认服务整个桌面；选中“针对该区域对话”后，输入框显示目标名称及小预览，并提供“退出区域对话”。未退出前持续针对该区域，不因一次回复自动切换目标。

助手回答留在可收起的对话层。简单操作成功用短反馈，如“图片已放入”，不强制弹开大段回答遮住结果。复杂任务可展开执行过程，但桌面仍可浏览。

## 5. 创建区域与放入内容

### 5.1 标准路径

1. 点击“定制桌面”，进入定制模式。
2. 在空白处用画线方式画一个圆或长方形，实时展示笔迹。
3. 松手规整形状，生成并保存空白区域；选中区域，原输入框关联该区域。
4. 点击“完成定制”恢复浏览。后续内容由用户提出需求，技术执行方式另行讨论。
5. 不展示撤销/重做按钮，不以绘制区域触发生成或开发。

绘制中的笔迹尚未保存，取消手势即消失；识别并创建后的区域立即保留，刷新可恢复，不以用户提交内容需求作为保存前提。

### 5.2 默认决策

- 未指定图片：自行选用随产品提供、可合法使用的素材；不默认使用用户截图、私人照片或无授权资源。
- 未指定颜色、圆角、标题：遵循桌面样式，先做出可修改结果。
- 用户给了附件：优先使用本次附件，避免忽略素材自行替换。
- 需求明确且可撤销：直接执行，不追问“是否需要我做”。
- 缺少必要访问权限、目标存在多个不可区分对象，或涉及付费/发布/业务数据删除：说明唯一关键缺口，再询问。
- 尚无能力：明确显示“正在创建功能”及实际阶段；不把说明文字写进区域冒充结果。

不得通过写死某个用户的区域 UUID、浏览器缓存迁移规则或匹配历史回复，代替通用的区域操作通道。

## 6. 区域上下文、会话与执行协议

### 6.1 会话

每个正式区域拥有独立的逻辑对话上下文，用户无需手动建会话。首次需要模型时再创建/绑定执行会话；简单本地动作不必调用模型。

桌面总对话与区域对话分开保存。切换区域恢复各自草稿和历史，不能把上一块区域的未完成回复写入当前区域。打开完整会话是可选查看动作，不是每次修改的必经步骤。

### 6.2 专用 prompt 必须携带

- 桌面与区域身份、当前组件类型、内容版本。
- 当前尺寸、设备视口、输入方式；不让模型凭手机型号猜坐标。
- 当前内容的必要摘要、用户附件、该区域最近相关修改。
- 当前可用能力及权限、支持的结构化操作。
- 用户本次指令；默认直接执行可撤销修改，补足非必要偏好。
- 禁止把普通回答当组件结果，禁止声称未完成的操作已经完成。

Prompt 约束行为，执行协议保证结果。两者不能互相代替。

### 6.3 执行闭环

需求 → 解析区域操作 → 校验能力/权限/内容版本 → 执行 → 持久化 → 界面应用 → 成功反馈。

每次操作具有 operationId、regionId、baseVersion、action、状态和结果版本。模型只能提交受支持的结构化操作，例如设置图片、绑定数据源、更新组件配置；不直接注入任意 HTML/JavaScript。

执行成功必须包含：数据或配置已保存、目标组件已接收结果。模型回复完成不等于组件更新完成。网络重试按 operationId 去重，不重复创建组件或启动业务。

同一区域快速连续修改按顺序执行；新需求替代旧需求时明确取消/废弃旧结果。区域已删除、用户已撤销或版本已变化，迟到结果不得复活区域、覆盖新内容。

## 7. 定制桌面与画线创建区域（2026-09-22 确认）

仅保留一个“定制桌面”入口；进入后按钮变为“完成定制”，点击退出。定制模式禁止浏览器文字选择和长按选词；普通浏览保持内容交互和滚动。不用长按作为进入定制的必要路径，不显示常驻组件调整按钮。

已有组件：定制模式点击选中，按住拖动；选中后显示尺寸手柄和更多菜单。菜单保留针对区域对话、固定/取消固定、从桌面移除。固定锁定位置和尺寸，不停止业务更新。退出后恢复业务点击。

空白处：手指、鼠标或笔画线，实时显示笔迹；松手后本地识别并规整为圆形或长方形。不是按起终点拉框；点击、直线、很小的涂画和未闭合路径不创建区域。识别不明确时让用户选择圆形/长方形，不硬猜。创建范围与既有组件重叠时不覆盖原组件。

画完即保存并选中区域，原输入框指向该区域。不发消息、不调用模型、不创建业务或启动自动开发。区域内容自定义的实现方式及整个 Negus 技术分层另行讨论。

形状只由用户决定，不限定内容。用户在圆形中要求表格也照做，助手后续按需求安排，不擅自改成长方形或换成其他内容。此次仅实现画区域，尚不实现表格等内容的生成与布局。

触摸取消、窗口变化或失焦取消未提交手势；松手提交布局。圆形在不同视口保持正圆，不随矩形容器拉伸成椭圆。最小区域沿用逻辑网格约束；不声称像素级自由布局或已达到手写笔商业产品的识别率。

## 8. 恢复操作：通过助手，不提供撤销入口（2026-09-22 确认）

取消桌面的撤销、重做按钮，以及成功后附带的撤销提示。用户需要恢复时，直接向助手提出“改回刚才那样”等需求。

这条替代旧稿的两套撤销工具栏设计。后文案例中的“撤销/恢复”表达用户恢复结果的需求，凡涉及点击撤销按钮、重做按钮的旧描述均不再采用；恢复交互统一为对话。实际恢复能力需要与区域内容自定义的执行方式一起讨论，本轮不能声称已实现助手恢复。

移除桌面区域不删除后台业务数据，不停止任务。此次移除不会自动触发另一次业务操作；系统不把已移除区域因迟到的生成结果复活。

## 9. 组件规格

### 9.1 图片

图片在区域内完整可用，无需标题栏占据主要空间。圆形展示使用等宽高裁切框和 object-fit，居中、随区域缩放，不溢出。支持替换、裁切形状修改、撤销和恢复。资源不可用时保留组件，显示“图片加载失败”和重试，不变回空区域。

### 9.2 当前任务

默认三条：对话标题、用户最新指令、状态。正在执行的任务优先；没有运行项时显示最近明确完成项。长期 Goal 与单轮回复状态分清，不把 idle 当完成。

三条必须完整容纳。加载、故障、重试不能额外占一整条任务空间；标题区用紧凑状态入口，详情解释失败来源。放大看概览，再看完整列表；点单项进入原会话。

### 9.3 自动化任务

默认展示名称、启停状态、周期、下次执行；详情提供来源、最近触发、执行记录和管理入口。

“已启用”依据配置，“执行中”依据运行事件，“已完成/失败”依据终态记录。没有运行记录就显示“暂无执行记录”，不推测成功或从未执行。

任务源必须登记覆盖范围与最后同步时间。未接入来源不能纳入“全部后台任务”承诺；主界面可标“Codex 自动化”，来源详情展示接入范围。系统计划任务、外部服务分别接入后才汇总。检测任务不创建新任务、不额外调用模型。

暂停/恢复需要调用真实调度端并核验结果；没有写能力时只给已有管理入口，不展示无法兑现的按钮。移除桌面卡片与停用自动化始终分开。

### 9.4 业务扩展

审图组件：接真实图片集合，显示今日待审，逐图批注、通过/退回，保留意见与版本。素材目录：接获授权的真实路径，显示文件、访问和预览。不能以助手提供的文字清单宣称完整审核/文件管理已实现。

## 10. 状态与异常

| 状态 | 用户看到 | 可做什么 |
| --- | --- | --- |
| 首次加载 | 固定尺寸骨架或简短加载状态 | 浏览其他区域 |
| 已有内容刷新 | 保留内容，轻量刷新指示 | 正常使用允许的操作 |
| 执行中 | 该区域显示正在进行的具体动作 | 取消本次动作、查看过程 |
| 成功 | 更新后的内容；简短成功反馈 | 继续修改、按动作撤销 |
| 失败 | 具体失败动作，如“图片加载失败” | 重试或重新选择素材 |
| 断线 | “连接已断开”，快照时间在详情 | 重连后恢复，不自动重复业务写入 |
| 配置缺失 | 明确指出缺什么 | 进入设置，不要求用户排查代码 |

正常状态不展示“可能不准确”等泛化说明。故障不能用删掉警告伪装成功。页面顶部连接状态只表示连接，不使用“网页已同步”暗示所有组件数据均成功；组件刷新情况独立表达。

## 11. 响应式、性能与动画

- 使用桌面内容区相对坐标和逻辑网格，不使用隐藏物理像素、不依赖硬件营销名称。
- 同时考虑视口、缩放、安全区、滚动和软键盘；键盘出现不能让目标区域或发送按钮不可达。
- 手机默认双列；用户主动放大的组件按布局显示。最小尺寸由组件能力决定，不能裁掉必要操作。
- 大小变化仅重排展示，不改变业务状态。不同设备布局同步需另有冲突策略；首阶段明确仅当前设备布局。
- 反馈目标：按下/选中 100ms 内可见；本地简单修改 300ms 内完成；缓存首屏 500ms 内出现。作为验收指标，需实测记录，不提前宣传已达成。
- 手势用 transform/预览层及帧调度，提交时持久化，不逐帧写缓存；目标在代表性手机稳定接近 60fps。
- 动画通常 120–180ms，遵循减少动态效果设置；拖动时不播放妨碍定位的回弹动画。
- 隐藏页面暂停无必要轮询，可见恢复；不靠大量模型请求维持界面更新。

## 12. 数据、安全与恢复

区域身份、布局、组件配置、素材引用、会话绑定、操作历史分开存储。删除布局不能级联删除业务任务或原文件。用户数据失败时保留最后成功版本，不能初始化成空桌面覆盖原数据。

自动保存必须有真实持久化结果。配额不足、写入失败显示“保存失败”，不要先标成功再静默丢失。多标签页通过版本检测避免互相覆盖；跨设备服务化未实现前不声称同步。

素材不得暴露本机绝对路径或访问凭据；服务端文件访问沿用授权。区域操作只操作所选对象，跨区域/业务写入需要明确指令。语音未来复用相同操作协议，不另建一套权限与撤销逻辑。

## 13. 验收用例

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| A01 | 手机画框说“放一张圆形图片” | 不追问素材，出现实际圆图，非文字回复 |
| A02 | 圆图展示 | 图片加载成功、宽高相等、居中；窄屏不变椭圆 |
| A03 | 撤销添加图片 | 只移除图片，区域位置与身份保留 |
| A04 | 撤销/重做移动 | 只改布局，不回滚期间新增业务数据 |
| A05 | 移除后撤销 | 同一组件恢复，无重复后台任务 |
| A06 | 正常/编辑模式长按 | 均打开正确菜单，松手不误关、不误触底层 |
| A07 | 滚动、触摸取消、旋转 | 不误建区域，不提交半次拖动 |
| A08 | 固定与碰撞 | 自己和邻居都不能改变其布局；业务继续更新 |
| A09 | 切换两个区域提出需求 | 各自上下文、草稿与结果隔离 |
| A10 | 旧请求迟到/重试 | 不覆盖新结果、不复活已移除区域、无重复执行 |
| A11 | 三条当前任务+同步失败 | 三条完整可见，故障入口不挤掉内容 |
| A12 | 自动化正常/暂停/执行中/失败 | 每种状态有对应真实证据，不用配置推断运行 |
| A13 | 断网与读取失败 | 快照有标识，恢复后补查，不误报空列表 |
| A14 | 刷新与存储失败 | 内容和历史正常恢复；失败不覆盖原桌面 |
| A15 | 手机键盘、长标题、多任务 | 无横向溢出、无关键按钮裁切、输入目标明确 |
| A16 | 无模型的简单操作 | 直接应用、可撤销，不创建多余会话或消耗模型 |

必须检查正常、空、加载、失败、长文本、固定、小尺寸、键盘展开等状态的实际页面。构建和接口成功不能替代截图检查；截图检查不能替代真实操作；隔离测试必须注明数据性质。发布前记录已测视口、真实数据来源和未通过用例。

## 14. 演示与推广验收

一条完整演示：空白桌面画框 → 说“放一张圆形图片” → 图片出现 → 说“换一张” → 只换图片 → 撤销 → 恢复前图 → 移动和固定 → 新区域展示真实自动化 → 查看执行记录。

另一条业务演示：今日待审图进入桌面 → 点图批注 → 审核结果保存 → 次日内容更新，位置与审核习惯保留。

演示不得依赖隐藏的特定区域 ID、人工改缓存、假任务或剪掉失败步骤。尚未具备的审图、语音、跨设备能力不纳入已交付宣传。

## 15. 当前实现差距与实施顺序

1. 先重建操作记录与分层撤销，修复“撤销内容导致区域消失”；不再叠加单一快照补丁。
2. 建立区域结构化操作通道和逻辑会话绑定，让图片设置等能力走同一协议；移除针对特定区域的临时注入。
3. 完成图片闭环：选区、指令、执行、保存、撤销/重做、刷新恢复与失败处理。
4. 按同一标准接当前任务与自动化；处理真实同步故障，验收三条任务在异常状态下仍完整显示。
5. 基础闭环通过上述用例后，再加入审图和素材目录。语音与跨设备最后接入同一执行模型。

本次 PRD 不代表上述差距已经修复，也不授权顺带重构对话、调度或其他模块。后续按用户确认的范围开发，以实际页面与验收用例交付。

## 16. 投资人视角：10 个真实使用案例与预期结果

补充日期：2026-09-21。以下为目标体验，不是现有能力清单。判断标准是用户能否将一句需求变成每天持续使用的工作入口。以实际结果倒推设计，而非以技术模块数量衡量价值。

### I01 随手放一张圆形图片｜新增、修改、撤销

用户框出区域说“放一张圆形图片”。区域立即出现选好的圆图，居中、无标题和说明书，不要求用户先上传。继续说“换成山景”，原位换图；说“小一点”，图片缩小，区域不移动。选择“撤销更换图片”恢复上一张，区域不能消失。

投资人期望：第一次使用就能感受到一句话改变桌面的掌控感。由此要求低风险默认决策、直接结果和内容级撤销。

### I02 每天审核待发布图片｜新增、使用、持续更新

用户说“把今天准备发的小红书图片放这里，以后每天审核”。半宽卡顶部为“今日待审 · 8 张”，主体是实际图片封面，底部“开始审核”。点开放大，左右切图，逐张批注“AI 味太浓”“人物不像同一个人”，选择通过或退回。完成后显示“已通过 5 张 · 待修改 3 张”；第二天换成当天素材，昨天的意见可回查。

投资人期望：每天有真实工作要回来处理。由此要求真实素材来源、批注与版本保存、按日期更新，不以聊天清单替代审核。

### I03 看清并控制自动化｜新增、查看、控制

用户说“把定时任务放这里，我要知道后台在跑什么”。紧凑卡显示“自动化 · 4 项启用”，三行分别为“每日资讯整理／等待执行／明早08:00”“素材同步／执行中／18/30”“服务巡检／已暂停／—”。详情可看周期、结果、历史并暂停。暂停成功后取消下次执行；失败保留原状态。仅在有对应数据时显示进度。

投资人期望：用户敢委托持续工作，因为看得见、管得住。由此要求运行与配置分离、控制结果核验；未接入来源不能包含在“全部后台任务”的承诺里。

### I04 存档素材随手打开｜新增、浏览、筛选

用户说“把之前存档素材的文件夹放这里”。唯一匹配直接接入，多个匹配以目录候选供点选。卡片顶部为目录名和搜索入口，下面展示图片缩略图、视频封面、文档图标。点开可预览或进入目录。继续说“只看视频”，原卡变成视频列表，不生成第二张卡。

投资人期望：减少寻找与切换，提高原有资料的使用价值。由此要求稳定目录绑定、真实预览、就地修改筛选。

### I05 随时知道助手在做什么｜新增、查看、跟进

用户说“这里显示正在跑的事情”。半宽卡完整展示三条，每条为标题、最新指令和状态；长期任务标“持续执行”，单轮标“处理中”。无运行项时显示“最近完成”。点单项进入原任务，回来保留桌面位置；完成后出现“报告已生成 · 查看”等真实结果入口。

投资人期望：用户可以同时委托多件事，不必守着聊天窗口。由此要求实时状态、原任务导航、紧凑布局，错误提示不得挤掉第三条。

### I06 一句话建立经营看板｜新增、使用、下钻

用户说“放本月生意情况，重点看收入和没收回来的钱”。接入数据后，卡片上方为“本月收入”“待收款”两个数字，下方收入趋势与“逾期应收3笔”。点数字展开客户、金额、到期日，再进入单笔详情。未接入时显示“连接账单”，不能展示虚构数字或示例趋势。

投资人期望：持续帮助经营，产生付费理由。由此要求可追溯指标、下钻和明确接入动作。

### I07 连续修改组件外观｜修改、继续修改、撤销

用户对审核卡说“图片放大一点，别显示文件名，只留审核状态”。原卡显示大图和审核状态，历史意见与来源保留。继续说“改回刚才那样”，只恢复展示方式，不撤回已完成审核、不修改其他卡。

投资人期望：用户能将产品调整成自己的习惯。由此要求展示配置与业务数据分离、区域上下文连续。

### I08 用手整理工作布局｜移动、缩放、固定

长按审核卡，进入调整，拖到顶部并拉宽整行；未固定组件平滑让位，不重叠。把当前任务固定在右侧后，再整理其他区域不会挤走它，任务仍更新。退出编辑后，手指恢复滚动和业务点击；旋转和大屏下不变形、不裁按钮。

投资人期望：形成稳定空间记忆。由此要求模式清楚、碰撞规则、固定语义与响应式适配。

### I09 放心移除和恢复｜删除、撤销、继续使用

长按自动化卡选择“从桌面移除”。卡片消失，反馈“已移除自动化组件 · 撤销”；后台任务照常运行。撤销恢复相同位置、身份、固定状态、筛选和数据源。若用户说“停止每天的资讯整理”，则停用对应业务任务，不能仅移除卡片。

投资人期望：低学习成本、低误操作代价。由此要求入口移除与任务停用分开、完整恢复而非新建空卡。

### I10 一句话布置每日工作台｜批量新增、布局、修改、使用

用户说“给我布置内容运营桌面，上面看任务，中间审图，下面放素材”。生成上方半宽当前任务和半宽发布安排，中间整宽今日待审，下方素材库。已有数据直接绑定，缺目录仅在素材卡内选择，不阻断其余功能，也不删除旧组件。说“发布安排不要了，审核区放最上面”，就地调整。第二天布局保留、内容更新。

投资人期望：交付完整工作环境，而不是让用户学习配置工具。由此要求组合操作可追踪、部分失败不拖垮整体、布局长期保存。

投资评估优先看 I02、I03、I10：分别验证日常使用价值、持续委托的可控性、完整环境交付能力。I01 是体验门槛，不能以复杂能力掩盖基础操作失败。

## 17. 普通用户视角：另外 10 个具体案例

这些案例从“我今天想完成什么”出发，不要求用户先知道组件名称。除明确的数据与权限接入外，默认直接完成可撤销操作。提醒、分享等只有实际送达能力可用后才能承诺。

### U01 出门前一眼看天气｜新增、查看、改城市

**我会说：**“放个杭州天气，我早上出门看。”

**我看到：**半宽小卡，大号温度、天气图标、城市名，下面三段小时天气和降雨概率，底部是更新时间。点开可看未来几天。说“改成上海”，同一张卡换城市，位置和尺寸不变。

**我期待：**不用每天再问天气。首次不必索取定位；指定城市即可使用。刷新失败保留带时间的上次天气，不能当作今日最新值。设计应支持固定地点与后台更新，天气只读不会擅自创建出门提醒。

### U02 把今天三件事记下来｜新增、使用、删除条目

**我会说：**“这里记一下：买牛奶、取快递、晚上整理照片。”

**我看到：**一张“今天要做”清单，三行勾选框，顶部“0/3”。点勾“取快递”，该行划线并移到已完成分区，顶部变1/3。说“再加上交水费”，原卡增加一行；说“牛奶不买了”，只删对应条目，反馈可撤销。

**我期待：**点就能用，不必每次聊天。清单是手动记录，不会自动创建通知、下单或假定每天重复；桌面卡移除也不等于抹除清单历史。

### U03 学习时放一个25分钟计时器｜新增、开始、暂停、继续

**我会说：**“这里放一个25分钟的专注计时器。”

**我看到：**方形卡中央大字25:00，下方“开始”。点击后变成倒计时与暂停按钮；暂停停住，继续接着走。说“改成40分钟”，未开始时直接更改；计时中明确显示是将本次总时长改成40分钟，已用时间保留。

**我期待：**切换页面再回来时间正确，不是后台暂停了就少算。结束显示“本次专注完成”；有通知权限才发送系统提醒。重置要明确作用于计时，不会删掉整个卡。

### U04 固定一张喜欢的照片｜新增、替换、调整展示

**我会说：**“这里放一张科比的照片。”

**我看到：**区域直接出现可辨认的科比真实照片，保持比例，不出现照片搜索建议或长说明。来源在详情。随后“裁成圆形”“脸放大一些”只调整这一张；“换一张比赛中的”换成经过核实的比赛照片。

**我期待：**系统自行选图，不让我为随意装饰先找素材；真实照片不能用生成图顶替。换图失败保留原图；撤销换图恢复上一张，区域仍在。具体来源许可决定图片可否用于公开传播，不能默认连推广授权也已取得。

### U05 收好稍后要看的链接｜新增、打开、排序、移除

**我会说：**“这些文章放这里，我周末看。”并粘贴三个链接。

**我看到：**“稍后阅读”卡，每条有标题、网站名和小封面；无法提取标题的链接仍以域名和网址保留。点击打开原文，返回桌面位置不变；可标已读，长按条目调整顺序。

**我期待：**删一条书签不会删除网页，也不清空整卡；打不开时仍能复制原链接。“周末看”不自动等于创建周末推送，提醒需有明确指令。

### U06 临时用一个换算器｜新增、输入、改用途

**我会说：**“做饭时要用，这里放个克和盎司换算。”

**我看到：**小卡有两个输入框“克”“盎司”，输入100克，另一边即时显示约3.53盎司；有交换方向按钮。无需每次发送消息。

**我期待：**单位明确、输入即有结果。说“再加毫升”时不能假定所有食材克和毫升等价，应在卡内增加食材选择；确定为水后才能换算体积。错误输入在字段附近提示，不弹整屏错误。

### U07 计划周末短途出游｜新增、修改、勾选使用

**我会说：**“这里帮我安排周六去杭州玩一天，从上海出发。”

**我看到：**整宽“周六杭州一日游”卡，按上午/中午/下午分段，包含地点、建议停留时间和地图入口，下方独立打包清单。未查询的班次不写成已确认车票，不擅自订票。

**我期待：**说“别太赶，把最后一个景点去掉”后，行程在原卡重排，打包清单不消失。点地图可导航；核实不了营业时间的景点不假装已经核实。天气或时间变化建议修改，不能偷偷替我改已确认行程。

### U08 手指误拖后恢复｜移动、撤销、重做

**我会做：**在编辑模式把天气卡从左上拖到右下，觉得不顺手，点“撤销移动天气”。

**我看到：**只有天气卡回原位；期间更新的温度和其他清单勾选不回退。点“重做移动天气”再次到右下。普通浏览时滑动页面不会误拖卡片。

**我期待：**撤销名称告诉我会发生什么，不是一个猜谜箭头。编辑中来电或手势中断，卡片回到上次确定的位置，而不是停在半路或被删掉。

### U09 清理临时卡片后找回｜批量选择、移除、恢复

**我会说：**“旅游结束了，把行程和打包清单从桌面收起来。”

**我看到：**两张目标卡高亮，系统移除明确匹配的两项，反馈“已收起2项 · 撤销”。照片、天气和其他清单不动。点撤销同时恢复两项及原先勾选状态；之后可从“已移除”找到它们。

**我期待：**“收起来”不会删掉旅行资料和照片。若有多个不同旅行行程，只让我选具体那一组，不误删所有。移除与彻底删除资料必须是不同动作。

### U10 手机小屏整理与断网恢复｜缩放、固定、使用、恢复

**我会做：**把待办卡拉宽，把照片缩小，把计时器固定；然后在地铁里断网，再回来。

**我看到：**待办文字完整、勾选按钮易点；照片按比例缩放；固定的计时器不被挤走。断网仍显示已保存内容，本地勾选立即反映；需要联网的天气显示断线状态和上次更新时间。恢复网络后更新天气，不能把离线勾选覆盖回旧状态。

**我期待：**刷新不丢布局，软键盘弹出能看清输入和目标。第一阶段仅保证当前设备；以后跨设备时应明确同步完成与冲突处理，不能承诺电脑立刻收到实际上未上传的修改。

## 18. 从20个案例倒推设计与验收优先级

| 操作 | 用户共同期望 | 定义与验收依据 |
| --- | --- | --- |
| 新增 | 说用途后出现能看的内容或能用的控件 | I01/I10、U01–U07；非必要偏好不阻塞，数据未接入不造假 |

优先验收“放照片→改裁切→换图→撤销，区域保留”和“新增清单→勾选→移动→撤销移动，勾选保留”两条最短闭环；再扩展到真实业务任务。投资价值看持续使用和完成工作的结果，普通用户满意度看一次成功、少追问、不丢失、能恢复。所有案例中的数字用于说明目标组件长相，正式产品必须显示真实用户数据。

## 16. 投资视角：10 个用户案例与预期效果

本节将用户已讨论的 10 个案例归档为体验目标，不作为已实现清单。投资判断关注：用户是否能得到结果、是否持续回来使用、是否敢把真实工作交给产品、是否愿意为节省的时间付费。以下示例数量与金额仅用于说明组件形态，不是产品运行数据。

### I01 随手放一张圆形图片

- 操作：新增 → 修改 → 撤销。
- 用户说：“放一张圆形图片。”随后说“换成山景”“小一点”。
- 组件形态：区域内只有一张居中圆图，无多余标题、说明或聊天记录；图片等宽高裁切，不变形。
- 预期效果：自行选用合适素材直接呈现；更换图片、缩小图片均保留区域位置。“撤销更换图片”恢复上一张，区域不消失。
- 投资价值：第一次操作就建立“说出来能改变桌面”的掌控感。这是体验门槛，不是收费核心。

### I02 每日图片审核

- 操作：新增 → 使用 → 持续更新。
- 用户说：“把今天准备发的小红书图片放这里，以后每天在这里审核。”
- 组件形态：半宽审核卡，顶部“今日待审 · 8 张”，主体封面缩略图，底部“开始审核”。放大后左右切图，旁边可批注、通过、退回。
- 预期效果：对单图写“AI 味太浓”“人物不像同一个人”；提交后统计变成“已通过 5 张 · 待修改 3 张”。次日显示当天素材，昨天意见留在历史中。
- 投资价值：承载每天真实发生的工作，形成持续使用习惯；必须接真实素材与持久审核记录。

### I03 看清并控制自动化

- 操作：新增 → 查看 → 控制。
- 用户说：“把定时任务放这里，我要知道后台在跑什么。”
- 组件形态：紧凑卡，顶部显示已接入来源及启用数量；三条预览分别展示任务名、状态、下次执行。例如“每日资讯整理／等待执行／明早 08:00”“素材同步／执行中／18/30”“服务巡检／已暂停／—”。
- 预期效果：展开看周期和执行记录；暂停后真实调度停止安排下次执行。失败保留原状态并说明失败。只有来源全部接入后，才能称为全部后台任务。
- 投资价值：用户看得见、管得住，才敢授权持续运行。

### I04 存档素材随手访问

- 操作：新增 → 浏览 → 打开 → 筛选修改。
- 用户说：“把之前存档素材的文件夹放这里。”
- 组件形态：顶部文件夹名与搜索入口，下方图片缩略图、视频封面和文档图标，底部打开目录。
- 预期效果：唯一匹配目录直接接入；多个同名目录用可点选列表解决。图片可预览、视频可播放。“只看视频”直接修改原卡片筛选，不新增一张卡。
- 投资价值：减少找文件与应用切换，让既有资料成为工作入口。

### I05 随时掌握助手的工作

- 操作：新增 → 查看 → 跟进。
- 用户说：“这里显示正在跑的事情。”
- 组件形态：半宽卡完整容纳三条标题、最新指令和状态；长期 Goal 显示持续执行，单轮回复显示处理中，无运行项显示最近完成。
- 预期效果：点击进入原任务，返回后位置不变。完成后提供“报告已生成 · 查看”等实际成果入口；故障不能挤掉第三条。
- 投资价值：用户可以离开对话窗口并行处理工作，无需不断追问进度。

### I06 本月经营看板

- 操作：新增 → 使用 → 下钻。
- 用户说：“这里放本月生意情况，重点看收入和没收回来的钱。”
- 组件形态：上方“本月收入”“待收款”两项数字，下方收入趋势与“逾期应收 3 笔”入口；点数字展开客户、金额、到期日期。
- 预期效果：数据来自已连接账单，点某笔可查看详情。没有数据连接时只给连接账单入口，不填假数字或示例趋势。
- 投资价值：从临时问答进入持续经营管理，验证具体付费理由。

### I07 一句话调整已有组件

- 操作：修改 → 连续修改 → 撤销。
- 用户说：“图片放大一点，别显示文件名，只留下审核状态。”
- 组件形态：同一审核卡扩大图片占比、隐藏文件名，保留状态标识。
- 预期效果：来源、批注、审核结果不变。“改回刚才那样”只恢复展示方式，不撤销已提交审核，不影响其他卡片。
- 投资价值：用户可以逐渐形成自己的工具，不必推倒重建。

### I08 用手整理工作布局

- 操作：移动 → 缩放 → 固定。
- 用户长按审核卡，移到顶部并拉宽整行，再固定右侧当前任务。
- 组件形态：编辑时显示手柄与吸附轮廓；松手后整齐排布，其他未固定组件让位，不遮挡。
- 预期效果：固定组件位置不变、内容继续更新；退出编辑后恢复滚动。旋转或大屏显示不变形、不裁掉操作。
- 投资价值：稳定的空间记忆提高熟练度，桌面越用越顺手。

### I09 安心移除并恢复组件

- 操作：删除 → 撤销删除 → 使用。
- 用户长按自动化卡选择“从桌面移除”。
- 组件形态：原位置卡片消失，短反馈“已移除自动化组件 · 撤销”，其他卡片按布局规则排列。
- 预期效果：后台任务继续运行；撤销恢复同一组件的内容、筛选、固定状态与位置。“停止每天的资讯整理”则是另一个明确的业务操作，不以移除卡片代替。
- 投资价值：可恢复、后果清楚，用户才愿意尝试和整理。

### I10 一句话布置内容运营桌面

- 操作：批量新增 → 布局 → 修改 → 日常使用。
- 用户说：“上面看任务，中间审核今天的图片，下面放素材。”
- 组件形态：顶部两个半宽卡——当前任务、发布安排；中间整宽今日待审；下方素材库。
- 预期效果：已有数据直接接入，缺目录时只在素材卡选择，不阻断其他卡片；原有内容不擅自删除。“发布安排不要了，审核区放最上面”直接调整。次日布局保留、业务数据更新。
- 投资价值：交付整套可持续使用的工作环境，减少用户配置成本。

### 投资视角的验收重点

优先证明审图的日常使用价值、自动化的可控性、整套桌面的交付能力。推广演示必须经过“创建后继续使用、修改、恢复、次日再打开”，不能只展示第一次生成。图片案例验证基础操作是否顺畅，不能用它代替业务价值证明。

## 17. 普通用户视角：10 个日常案例与预期效果

普通用户不关心系统有哪些模块，只关心“我想做的事能不能顺手完成”。下面覆盖日常新增、删除、修改、直接使用，以及误操作、离开恢复、不同区域之间的边界。均为目标体验，不表示相关外部服务已接入。

### U01 出门前看天气

- 用户场景：每天早上要决定穿什么、带不带伞。
- 用户说：“这里放广州天气，告诉我今天要不要带伞。”
- 组件长相：小卡左侧天气图标，右侧温度，下方“广州 · 今天”和一句基于预报的出门建议；点开看逐小时降雨概率和未来几天。无需塞入整篇气象分析。
- 实际操作：首次直接使用明确指定的广州，不额外询问定位；说“换成深圳”就在原卡更新。天气有更新时间，预报用概率表达，不将预测写成保证。
- 预期效果：一眼得到出门决策需要的信息。数据读取失败保留上次更新时间和重试，不能显示旧天气冒充今天。
- 验收点：换城市不新增卡片，刷新仍记住深圳，天气图不挤掉温度。

### U02 随手记下要买的东西

- 用户场景：做饭时想到缺什么，希望快速记下，购物时逐项打勾。
- 用户说：“建个购物清单，牛奶、鸡蛋、洗衣液。”
- 组件长相：标题“购物清单”，下面三行勾选框和物品名，底部轻量“添加”入口；长清单在卡片内滚动，放大可看全。
- 实际操作：说“再加苹果，牛奶改成两盒”，原列表增补；到店直接点勾，不必聊天。划错一项可“撤销勾选”。
- 预期效果：已买项目折叠到已完成区，未买项目仍醒目；关闭页面后记录不丢。说“把这个清单从桌面拿掉”只移除入口，可恢复。
- 验收点：撤销勾选不能删掉整张清单；添加项目不能重复已有未完成项而不说明。

### U03 给妈妈生日设一个看得见的提醒

- 用户场景：怕忘记重要日期，不想研究复杂日历设置。
- 用户说：“10 月 12 日是妈妈生日，提前三天提醒我。”
- 组件长相：上方“妈妈生日”，中央大号“还有 21 天”（按实际日期计算），下方生日日期与“10 月 9 日提醒”；点开修改日期和提醒方式。
- 实际操作：当前年份未过则选本年，已过则明确显示下一年；没有说每年就不擅自设年度重复。通知渠道未授权时，在卡内完成授权或选择，并明确显示“提醒未开启”。
- 预期效果：倒计时可以先使用；只有提醒确实保存、通知条件具备后才显示“提醒已开启”。移除倒计时不会偷偷删除已经设置的提醒。
- 验收点：用户能区分“看见倒计时”和“会收到通知”，不把前者冒充后者。

### U04 做饭时用一个倒计时

- 用户场景：煮面时手忙，不想打开一堆菜单。
- 用户说：“放一个 8 分钟煮面计时器，现在开始。”
- 组件长相：中央大号 08:00，外围细进度环，下方暂停和重置；结束显示“时间到”。
- 实际操作：说“再加两分钟”立即更新剩余时间；点击暂停后时间停止，继续后接着计时。页面短暂切到后台再回来，按真实结束时间校正。
- 预期效果：用户一眼读懂剩余时间。音效或后台通知受设备权限限制时，在设置提醒时解决，不虚假承诺锁屏后一定响铃。
- 验收点：切回页面不会从 8 分钟重来；调整时间不产生第二个计时器；移除运行中的计时器需明确选择停止或保留提醒。

### U05 把常用网站放在手边

- 用户场景：每天都要打开邮箱、网盘和课程网站。
- 用户说：“这里放我的常用入口：邮箱、网盘、这个课程链接。”并附链接。
- 组件长相：紧凑的 2×2 图标宫格，每个图标下面一行名称；不足四项保留自然间距，不显示空白假按钮。
- 实际操作：点图标打开对应网站；长按入口可重命名、拖动排序或移除。邮箱、网盘具体服务不明确时显示可选服务，而非猜测私人账号。
- 预期效果：以后直接点击使用；删掉网盘入口不会删除网盘文件。外部登录仍在原服务完成，不索取密码填进聊天。
- 验收点：链接完整、名称可读、移动端触控不误点；新增入口不重置原排序。

### U06 安排一次周末短途旅行

- 用户场景：出发前想把行程、订房信息和待办集中起来。
- 用户说：“做一个周末杭州旅行卡，周六上午到，周日下午走。”
- 组件长相：整宽卡顶部日期与目的地，下面“周六／周日”两个页签，每天按时间展示少量行程；底部“酒店”“车票”“待带物品”入口。
- 实际操作：初次给出可编辑的行程草案，明确未预订。用户说“下午别排太满”“把西湖放到早上”，只改相关安排；拖动可调顺序，实际订单由用户提供或授权读取。
- 预期效果：点开就知道下一站去哪、资料在哪里。预算或时间未给够不阻止先做草案；订票、付费是独立确认动作。
- 验收点：建议与真实订单有明确区分；改行程不丢已附的酒店凭证，撤销只回退本次安排。

### U07 每天学几个单词

- 用户场景：希望在空闲时学五个单词，不想每天重新发问。
- 用户说：“这里每天放五个适合英语初学者的单词。”
- 组件长相：一张翻卡，正面大号单词和发音入口，背面中文释义与一句短例句；下方“认识／再练”和“今天 2/5”。
- 实际操作：直接点击翻面与标记；说“简单一点”调整难度，已学记录保留。每天首次打开准备新内容；若需要定时后台生成，另行明确设置并出现在自动化列表。
- 预期效果：每天回来能继续，不重复从零开始；五个学完显示完成，允许复习。发音未接入时不显示假播放按钮。
- 验收点：一天内刷新不重置学习进度；内容调整不清除历史，不暗中启动持续付费生成。

### U08 随手记录日常花销

- 用户场景：刚买完早餐或打完车，只想快速记一笔。
- 用户说：“放个记账卡，今天早餐 12 元，打车 28 元。”
- 组件长相：顶部“今日支出 ¥40”，下面两条记录“早餐 ¥12”“交通 ¥28”，底部“记一笔”；点总额查看本周分类。
- 实际操作：说“打车那笔改成 26”，总额随之变成 ¥38；误删早餐可撤销删除该笔。只展示用户录入或真实导入账目，不自动猜银行流水。
- 预期效果：记录、改错、查看都在原卡完成；说“只看这个月”修改统计范围，不重新建账本。
- 验收点：金额精确计算；撤销改金额不影响另一笔，移除卡片不删除账本。

### U09 用喜欢的照片整理一个舒服的桌面

- 用户场景：想让桌面像自己的手机首页，常用内容容易找到。
- 用户说：“把这张照片放这里，清单挪到上面，天气缩小一点。”并附照片。
- 组件长相：照片按选区裁切；上方清单更醒目，小天气卡占较少空间。编辑时才显示手柄，平时不布满工具按钮。
- 实际操作：优先使用附件；可以双指缩放照片裁切范围（若该手势已实现）或通过裁切面板调整，不把图像缩放误当区域缩放。布局变化后简短列出已执行的三项动作。
- 预期效果：照片内容修改和卡片位置调整各自可撤销；“撤销挪动清单”只还原位置，不能把刚上传的照片一起撤掉。
- 验收点：多项操作逐项可追溯；未成功的项单独反馈，不把部分完成说成全部完成。

### U10 大扫除桌面，误删后找回来

- 用户场景：旅行结束、活动结束后，想清理桌面但不丢记录。
- 用户说：“把旅行卡和生日倒计时从桌面移除，购物清单留下。”
- 组件长相：两个指定卡片被移除，清单和其他组件保留；短反馈显示“已移除 2 个组件 · 撤销”，编辑菜单提供“最近移除”。
- 实际操作：点撤销恢复本次两张卡；过一会只想找回旅行卡，可在最近移除列表按名称与缩略图单独恢复。重复名称时先高亮候选，避免删除错误对象。
- 预期效果：旅行记录、清单内容不会被擦除；生日通知是否仍开启在相关反馈中明确说明，并提供独立管理入口。恢复使用原身份与数据，不生成重复提醒。
- 验收点：留下的购物清单内容与位置按既定布局规则保持；刷新后仍能找回最近移除项；真正永久删除记录需要单独明确操作。

## 18. 用案例倒推桌面定义

### 四种基础操作的统一体验

| 操作 | 用户期待 | 产品必须提供的结果 |
| --- | --- | --- |
| 新增 | 说完就有东西可用 | 合理默认值、实际组件、必要接入就地完成；不交付一段说明 |
| 修改 | 在原有成果上继续调整 | 保留身份与无关数据，显示本次变更，按动作撤销 |
| 删除 | 只拿掉我明确指定的东西 | 明确对象、布局和业务分离、可恢复、不暗中停任务或删文件 |
| 使用 | 不必每次找助手 | 看、点、勾选、筛选、预览、填写等直接交互；结果保存并能继续 |

### 贯穿 20 个案例的验收要求

- 首次生成不是终点：必须验证修改一次、撤销一次、刷新一次和再次使用。
- 能自行补足的非必要偏好直接决定；确实需要用户信息时提供最短选择，不转成需求问卷。
- 即时展示、持久记录、定时后台运行分别定义。不能把“每天打开更新”悄悄升级成后台自动任务。
- 组件有明确的最小可用形态：小区域展示关键内容，放大显示详情；不能把全文硬塞进小框。
- 普通用户看得见操作后果：撤销有动作名，删除有对象，任务有状态，成功有实际结果。
- 本节新增案例不自动扩张近期开发范围。先用 I01/I05/I03 与 U09/U10 验证基础操作，再按真实需求接入其他业务。
