## 推进方式建议

每次只确认一段用户体验，随后实现、隔离验证并供用户查看；根据实际体验调整，再继续下一段。助手负责技术选择、实现和验证，用户负责预期效果与体验。沿用员工、项目、会话和任务的既有基础，修改范围随场景确认，不预先指定整体重构。

用户打开桌面，在Negus对话入口发送：

> 帮我调研适合Negus的推广渠道，给出行动建议。

按以下顺序逐段讨论，每段通过后再推进：

| 段落 | 需要明确的用户体验 | 当前状态 |
| --- | --- | --- |
| 发出需求 | 用户在哪里说、看到谁接单、如何看见关联项目和任务 | 待讨论 |
| 执行期间 | 用户如何继续聊天、查看工作、补充要求及参与协作 | 待讨论 |
| 收到结果 | 谁向用户回复、回复在哪、如何追问和更新成果 | 待讨论 |

当前第一小步只讨论“发出需求”。助手候选建议：用户仍在桌面原对话，由Negus简短说明产品负责人接单；任务面板显示同一项工作的项目和负责人，不要求用户先建群或选择下属。此建议尚未确认，任务面板位置和样式未定义。
