## 核心表达

> **Negus：你需要什么工作功能，直接说出来。**

一个可以用自然语言不断定制的个人／企业工作空间。

- **有浏览器，就能进入自己的工作空间。** 手机、平板和电脑访问同一个已部署、获授权的工作区。
- **说出需求，把需要的功能加进去。** 每日资讯、项目进度、进销存入口，按实际需要创建和调整页面。
- **任何功能，任何位置。** 把报销上传放到员工首页，把会议预约放进项目，让员工的 AI 助手按授权传递工作事项。

后两项描述产品方向，具体场景须以相应实现和验收为准。

## 当前阶段介绍稿

Negus 正在建设一个可以用自然语言不断定制的工作空间。

目前，你可以通过浏览器进入已部署的 Negus，继续真实 Codex 工作，查看项目进度，并使用项目群聊、Agent 和交付物相关能力；各项体验成熟度以功能记录为准。

接下来，我们希望你能直接说：“给我加一个每日资讯页面”“把库存系统入口放到首页”“做一个公司的发票上传页面”。完成对应开发与发布后，新功能就出现在你需要的位置，之后还可以继续修改。

随着工作变化，让自己的工作空间持续变化。

## 首条演示建议（待实现与验收后拍摄）

场景：负责人在手机上提出“给公司加一个报销发票上传入口”。

1. 说明使用人员、上传内容和入口位置。
2. 查看 Negus 创建的页面预览，确认功能与访问范围。
3. 完成发布后，从员工首页打开入口。
4. 同事真实上传一张测试发票，负责人看到对应记录。
5. 再提出“增加费用归属项目字段”，展示修改后旧记录仍保留。

演示应展示真实页面、数据和结果；尚未完成的步骤标注为设计预览。记录实际耗时，不预设“一会儿”“一分钟”等交付保证。

## 宣传与商业验证边界

- 浏览器访问依赖后台服务在线和有效权限，不代表无需安装或配置任何运行环境。
- 创建一个入口与交付完整业务系统分别说明。正式账号、资源权限、自动部署、不中断更新和跨员工助手通信均按实际状态表达。
- “任何功能，任何位置”用于说明持续扩展的产品方向，不承诺所有业务即时实现。
- 关于 AI 改变 SaaS 的观点作为战略判断；公开介绍优先展示具体需求如何变成可用功能，不宣称已证明替代全部 SaaS。
- 建议通过首次功能交付时间、后续修改成本、旧数据保留情况和持续使用意愿验证价值；目标行业、收费方式和融资结论尚未确定。
- 本次仅更新宣传材料，没有对外发布。

## 内测宣传资产增量（2026-09-14 23:58 +08:00）

本节只记录当前代码和定向检查可以支撑的表达。浏览器、手机和公网实测完成前，仍须把下列演示标为“内测演示”，不能写成正式稳定承诺。

### 一条可复现的核心叙事

**从项目面板进入项目经理，再回到项目群聊继续工作。** 这条路径展示 Negus 作为工作空间的价值，不把尚未完成的页面自动生成或账号系统当作现成功能：

1. 用户打开项目管理页，查看项目目标、阶段、健康状态、当前计划和最近更新。
2. 用户点击“与项目经理讨论”，进入当前项目对应的长期 `manager` 员工单聊；标题区显示项目上下文。
3. 用户在单聊中明确说明项目和任务，例如“请根据当前项目计划，整理今天的阻塞和下一步”，再查看真实 Codex 的流式执行与最终回复。
4. 用户回到项目群聊，查看已保存的公共讨论记录；需要时按日期或历史页读取较早消息，再继续指定员工处理工作。
5. 群聊首次连接失败时，页面给出刷新恢复入口；执行失败或中止必须显示为失败或中止，不能伪装成完成。

拍摄前必须逐步录屏并记录浏览器、设备、网络和构建版本。项目经理入口当前为 `implemented_uncommitted`，真实员工 Runtime、点击路径和移动端仍待验收；群聊历史保存与分页读取是当前实现方向，但完整长期记忆、每日压缩和跨员工通用经验仍未交付。

### 内测邀请文案

> **Negus 内测招募｜把项目工作放进一个能持续协作的 AI 工作空间**
>
> 如果你正在多个 AI 对话、项目文档和群聊之间来回切换，欢迎参加 Negus 内测。你可以从项目面板进入项目经理 AI，继续真实 Codex 工作；也可以在项目群聊中调用员工 Agent，保存并回看公共讨论记录。
>
> 这是一轮小范围内测。我们希望你带来一个正在推进的真实项目，完成一次“提出任务 → AI 执行 → 查看结果 → 回到项目继续跟进”的流程，并告诉我们哪里卡住、哪里需要重试、哪些信息应该长期保留。
>
> **适合参加的人：** 正在管理研发、内容、运营或小团队项目，并愿意提供具体反馈的人。
>
> **参加前请知道：** 当前版本仍在验证登录、远程访问、移动端体验、权限边界和长时间运行；它不是正式商业服务。请使用脱敏数据，不要上传密码、身份证件、客户隐私或不可恢复的生产资料。
>
> 申请时请留下：项目类型、最想交给 AI 的一项工作、常用设备，以及愿意参加一次反馈回访的时间。

### 功能与限制口径

| 对外可以展示 | 对外必须说明的限制 | 当前宣传状态 |
| --- | --- | --- |
| 浏览器/PWA 进入工作区；电脑和移动设备使用同一产品入口 | 依赖后台服务在线、网络可达和有效授权；固定公网入口的长期稳定性仍在验证 | 可作为体验入口，内测说明 |
| 真实 Codex 对话、发送、流式过程、停止、恢复、历史、复制、归档和分叉 | 各功能仍有待真实刷新、重开、跨端和长任务验收的项目记录 | 仅展示已通过对应检查的路径 |
| 项目管理页查看计划、进度、更新，并进入项目经理单聊 | 当前入口只提供项目上下文定位，不自动替用户发送任务；真实员工 Runtime 和移动端待验收 | 内测演示，不作稳定承诺 |
| 项目群聊、`@` 员工、员工结果回群和公共历史分页读取 | 群聊长期记忆、每日压缩、通用经验沉淀尚未完成；失败恢复仍需真实环境验收 | 小范围内测 |
| 图片、音频、视频、文件附件，以及 HTML/PDF/Artifact 预览和下载 | 上传链路仍是 Demo 级，真实大文件、失败重试和多端草稿保持未完整验收 | 只用脱敏小文件演示 |
| 自然语言生图与连续改图（真实对话链路） | 专门工作台、批量、队列和定时任务仍在开发 | 可按已验证会话演示 |
| “需要什么工作功能，直接说出来”的产品方向 | 任意位置页面自动生成、真实业务数据连接、版本回退和跨功能复用的一体化能力尚未验收 | 作为愿景和后续路线，不写成现成能力 |
| 项目经理、员工 Agent 和群聊协作 | 现有多个 Agent 不等于多名真人各自 AI 助手已经可以自由通信 | 只宣传已实现的项目内协作 |

明确暂不宣传：正式账号注册与开放创建、公网链接自助生成、企业级多租户权限、跨员工助手通信、Desktop/Web 同一任务实时会话锁，以及“无需后台运行”“固定几分钟生成任何系统”等表述。

### 给投资人的简报要点

- **问题：** 项目工作被分散在聊天、文档、任务列表和多个 AI 工具中，负责人需要反复搬运上下文并确认结果。
- **产品切口：** Negus 把项目面板、项目经理 AI、员工 Agent、公共群聊、历史记录和交付物放到同一工作空间；用户从一个项目入口开始，而不是先理解一套工具菜单。
- **可验证证据：** 当前仓库已有真实 Codex Web 对话、项目群聊、多 Agent、附件、HTML/PDF/Artifact、PWA 入口；项目面板已加入项目经理单聊入口，群聊具备公共历史读取和失败恢复提示的代码路径。
- **差异化假设：** 长期价值不在一次回答，而在工作空间能持续保留项目上下文，并逐步按自然语言增加和调整功能。这个假设仍需要内测中的重复使用、修改成本和留存数据验证。
- **增长叙事：** 先用“一个项目，一个 AI 经理”让用户在具体工作中上手，再用可持续定制的页面和流程扩展到更多团队；每个案例必须展示真实任务、结果和后续修改。
- **当前风险：** 正式账号与公网入口、权限隔离、真实业务页面、长期记忆、跨端连续性和会话锁仍是工程与信任门槛；不能用概念视频替代这些验收。
- **阶段判断：** 当前适合小范围技术内测和问题收集，尚不应宣称公开商业化或已经替代完整 SaaS；下一轮融资叙事应以真实内测完成率、重复使用和用户愿意付费的具体工作为证据。
