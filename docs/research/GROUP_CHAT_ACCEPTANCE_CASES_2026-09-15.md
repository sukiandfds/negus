# Negus 群聊验收测试案例

日期：2026-09-15  
基线分支：`codex/publish-current-panel`  
基线 SHA：`0353352ba24e6e18a040437e5ba4bb28a1cef805`  
目的：从真实工作群场景反推群聊的交互、任务、会话、记忆和权限架构。

## 统一约定

- 真人消息显示在公共群聊时间线。
- `@员工` 是定向请求；未被点名的助手默认旁听，不抢话。
- “后台任务”拥有独立任务会话，可从任务卡打开；结果回传给负责人后才进入公共群聊。
- 工具调用显示开始、结果、失败和来源；不能只显示最终答案。
- 停止任务后不得继续写入结果；已完成的步骤和失败原因必须保留。
- 验收重点是用户是否知道谁在做什么、为什么这样做、如何继续操作。

## 案例 1：真人闲聊，助手旁听

**背景**：项目成员在群里讨论周末是否调整发布节奏，没有要求 AI 参与。

**模拟对话**：

```text
张三：这周发布节奏有点紧，周末要不要先缓一天？
李四：我觉得可以，客服那边最近也比较忙。
王五：那周一再看数据吧。
```

**系统交互**：群聊显示“AI 旁听中”，不创建任务、不插入回复；后台可记录主题，但不能把闲聊自动变成决策。

**验收标准**：

- 3 条真人消息正常保存并实时同步。
- 没有助手自动发言。
- 未经确认，不生成“已决定周一发布”的项目决策。

**反推能力**：旁听状态、主题识别、事实与决策分离。

## 案例 2：点对点沟通

**背景**：产品负责人只想询问产品助手一个问题，其他 Agent 只需要知道结果。

**模拟对话**：

```text
张三：@产品负责人 目前内测最可能卡在哪里？
产品负责人：我先检查需求、权限和部署链路。
系统：产品负责人正在分析，其他助手不会自动参与。
产品负责人：初步看是权限和失败恢复风险更高。
```

**系统交互**：只创建产品负责人的回答任务；其他成员看到一条普通回复，不创建后台任务。

**验收标准**：

- 只有被点名 Agent 执行。
- 其他 Agent 不抢答、不创建重复任务。
- 回复标明“初步判断”，不能伪装成已验证事实。

**反推能力**：定向路由、回答置信度、公共摘要。

## 案例 3：多人独立征询，避免单一视角

**背景**：用户想判断是否在 14 天内开启内测，担心被一个 Agent 带偏。

**模拟对话**：

```text
张三：请产品、开发、市场和风险分别独立判断：14 天内能否内测？先不要互相参考。
系统：已创建 4 个独立意见任务，结果将在汇总前保持隔离。
产品负责人：从用户流程看可以，但需要收缩首批用户范围。
开发负责人：核心路径可行，但群聊恢复和权限仍有缺口。
市场负责人：可以先做邀请制宣传，避免承诺全量稳定。
风险负责人：不建议直接公开，需先完成失败恢复验收。
主持助手：共识是可做小范围内测；主要分歧是权限和恢复是否达到上线门槛。
```

**验收标准**：

- 4 个 Agent 在看到其他意见前独立完成分析。
- 汇总区分共识、分歧、未知和建议验证项。
- 用户能打开每个独立意见的来源会话。

**反推能力**：独立意见轮、隔离上下文、主持汇总、分歧记录。

## 案例 4：负责人拆分后台任务

**背景**：开发负责人需要同时检查前端流程、服务端接口和测试覆盖。

**模拟对话**：

```text
张三：@开发负责人 检查群聊内测路径，给出可修复的问题。
开发负责人：我会拆成前端、服务端和测试三个后台任务。
系统：已创建任务 T-101 前端检查、T-102 服务端检查、T-103 测试检查。
开发负责人：三个任务完成后我会汇总，不直接把中间结果刷到群里。
```

**后台任务卡**：每个任务显示负责人、状态、进度、关联会话、最近事件和打开入口。

**验收标准**：

- 负责人是公开群聊成员；子 Agent 是后台任务执行者。
- 三个任务可并行执行，结果回传负责人。
- 用户能打开任一后台会话继续沟通。

**反推能力**：总助手/分助手、任务树、任务会话、结果回传。

## 案例 5：相关任务复用同一个分助手会话

**背景**：前一天已让研究分助手调查竞品，今天继续追问同一主题。

**模拟对话**：

```text
张三：@市场负责人 继续补充昨天的竞品调研，重点看 Grok Bot。
市场负责人：已识别为昨天的竞品研究任务，将继续使用研究分助手会话 S-201。
系统：S-201 已恢复，保留昨日来源和结论。
市场负责人：补充结果如下……
```

**验收标准**：

- 不创建无关联的新会话。
- 分助手能看到该任务已有结论和来源。
- 用户能看到“复用会话 S-201”的明确提示，并可选择新建。

**反推能力**：任务主题绑定、会话复用、显式新建入口。

## 案例 6：助手调用工具并展示证据

**背景**：产品负责人需要确认某个接口是否真的可用。

**模拟对话**：

```text
张三：@开发负责人 确认 /api/group/messages 是否支持按日期读取。
开发负责人：我会读取路由和相关测试，并运行定向测试。
系统：开发负责人调用工具：读取 group-routes.mjs。
系统：工具完成，发现支持 date 参数。
系统：开发负责人调用工具：运行 group-room-store.test.mjs。
系统：测试通过。
开发负责人：已确认支持按日期读取；证据是路由实现和测试结果。
```

**验收标准**：

- 工具调用显示开始、结束、结果或失败。
- 结论能引用文件、测试或外部来源。
- 工具失败时显示失败原因和下一步，而不是生成无依据结论。

**反推能力**：工具事件流、证据引用、来源可信度。

## 案例 7：真人纠正错误理解

**背景**：开发负责人误把“可查看历史”理解成“Agent 已具备长期记忆”。

**模拟对话**：

```text
开发负责人：群聊已经具备长期记忆。
张三：纠正：现在只是保存和分页读取历史，没有语义记忆。
系统：已将“长期记忆已完成”标记为错误判断，并保留纠正消息。
张三：请重新评估。
开发负责人：修正为：历史保存已完成，语义记忆尚未完成。
```

**验收标准**：

- 纠正消息进入公共上下文。
- 后续 Agent 不继续使用被否定的结论。
- 系统保留原判断、纠正者和修正后的结论。

**反推能力**：事实/判断/纠正状态、版本化上下文、决策来源。

## 案例 8：后台任务被停止

**背景**：研究任务调用外部资料过久，用户决定停止。

**模拟对话**：

```text
张三：停止市场研究任务。
系统：正在停止任务 T-301，等待当前工具调用安全退出。
系统：任务 T-301 已中断，未发布未完成结果。
市场负责人：任务已停止，已完成的 3 个来源仍可查看；需要时可以从断点继续。
```

**验收标准**：

- 停止的是指定任务，不影响其他群聊任务。
- 停止后不能继续写入最终结论。
- 已完成步骤、未完成步骤和中断原因可查看。
- 用户可以选择“从断点继续”或“重新开始”。

**反推能力**：按任务中断、取消令牌、部分结果保存、断点续作。

## 案例 9：群聊会议记录和实时提醒

**背景**：三名真人讨论上线日期，信息不完整且存在矛盾。

**模拟对话**：

```text
张三：周五上线。
李四：开发还没完成回滚验证。
王五：市场宣传已经排到周五。
记录助手：当前存在冲突：宣传按周五安排，但回滚验证尚未确认完成。
张三：先不要定案，记录为待确认。
记录助手：已记录待确认项：回滚验证负责人、完成时间、上线是否延期。
```

**验收标准**：

- AI 只在发现明显冲突或用户开启记录模式时提醒。
- 不把“周五上线”自动记录成最终决策。
- 讨论结束后可生成摘要、分歧、待办和未决问题，并链接原消息。

**反推能力**：讨论观察、冲突检测、会议记录、待办提取。

## 案例 10：后台结果汇总并沉淀到项目

**背景**：开发、产品和市场三个任务完成，负责人需要形成可执行结论。

**模拟对话**：

```text
开发负责人：三个后台任务都已完成，我先汇总。
开发负责人：结论：功能可以进入小范围内测，但必须先修复断线恢复问题。
张三：把“断线恢复”转成项目任务，负责人是开发负责人，优先级 P0。
系统：已创建项目任务 PM-401，来源为群聊消息和后台任务 T-101/T-102。
张三：把剩余风险记录为上线门槛。
系统：已创建风险 R-12，并关联本次讨论。
```

**验收标准**：

- 汇总明确引用了哪些后台任务和群聊消息。
- 可一键生成项目任务、风险、决策或文件产物。
- 项目面板显示来源、负责人、状态和关联会话。
- 后续从项目任务进入群聊时，能回到原讨论上下文。

**反推能力**：群聊到项目对象的写回、来源链、任务与会话双向跳转。

## 由案例反推的最小架构

1. **消息层**：普通消息、点名消息、群体征询、任务请求、系统事件分开建模。
2. **公共上下文层**：保存真人原话、AI 判断、纠正、事实、争议和决策，不能只保存纯文本。
3. **会话层**：每个公开员工拥有总助手会话；每个后台任务拥有可复用的分助手会话。
4. **任务层**：`discussionId` 管理一次讨论，`taskId` 管理子任务，`turnId` 管理一次 Agent 执行。
5. **事件层**：统一记录 Agent 回复、工具调用、任务状态、停止、失败和恢复。
6. **路由层**：默认旁听；`@` 定向；多人独立征询；负责人拆分后台任务。
7. **记忆层**：原始历史、结构化项目记忆、按需检索三层分离。
8. **项目写回层**：结论可转任务、决策、风险、文件和进度项，并保留来源链。
9. **恢复层**：断线、刷新、服务重启和任务中断都必须有可见状态，禁止静默重跑。
10. **权限层**：区分真人成员、员工总助手、后台分助手和工具权限。

## 最低内测通过线

- 案例 1、2、3、4、6、8 必须全部通过，才能验证基本群聊协作。
- 案例 5、7、9、10 必须通过，才能宣称具备持续项目协作能力。
- 任一案例出现静默丢消息、错误结论继续传播、停止后继续执行或后台结果无来源，均不能判定群聊达到内测标准。
