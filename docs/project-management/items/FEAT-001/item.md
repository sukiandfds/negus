# 单人 Codex Web 对话与控制

## 2026-10-30 缓存同步需求核对

以下是本次维护对话直接可见的用户原文，收录于2026-10-30；早先发言的精确日期未独立核实。下文8月状态仅是历史记录，不代表当前有效体验。

> 不只是配置列表，其他地方的缓存逻辑应该都要一起排查，我的要求是所有尽量同时加载缓存，加载更新，不要每个部分独立更新。你快检查一下，不确定的和我讨论

> 这些缓存相关，你看看这一周的相关修改记录，来来回回改那么多次，每次都被乱改

当前有效要求：先显示已有缓存；有关联的显示不能各自刷新造成矛盾、消失或闪烁；优先复用同步来源，排查不确定的体验边界先与用户讨论。不能把“减少代码”解释成可以删除这些行为保证。

不得再次采用的理解：仅因为代码名为页面快照就认为已有统一更新；仅凭测试通过就认为列表、正文、状态共同更新；将旧实现或助手总结当成用户对不同步的许可。

已被后续澄清替代的助手建议：不同对话谁更新完谁先显示。用户明确要求按批次一起展示，不得重新采用逐条发布。旧25日实现也不自动代表当前规则。

### 2026-10-30 批次与整条对话范围确认

来源：本次维护对话连续澄清，原话逐字收录；未取得消息级标识。下述场景说明是助手提供的提问上下文，不冒充用户原话。

用户说明最近10条的含义：

> 好混乱。我的10条的意思是，最后更新的10条内容先加载好，避免用户等太久。10条都好了一起展示。然后后续的更多变化再一起读取完再展示。由于我们消息列表也就展示最近10条消息在前面，其他的都要往下翻，所以我觉得这个逻辑是合理的啊？

场景1：前10条某条慢或失败；B为等到超时后一起展示成功部分，失败部分保留缓存。

> B，超时就显示报错且传对话id等用日志记录。

场景2：批次未完成时点开其中一条；A为先展示缓存，最新内容仍等本批完成，B为该条独立优先展示。

> 你建议呢？我觉得都行。要不先a。另一个看起来好复杂容易有新的错误。下一个吧。之后可以考虑b

场景3：加载期间发送消息，助手曾建议单独置顶，用户澄清：

> 我觉得，发送发送成功后也不用单独做什么逻辑了，本来就应该按照时间排序啊，我的意思是，我发出去的消息，等之前的内容加载出来之后，也理应排在最后，而不是需要特别处理和消息置顶啊？

此前用户已经说明立即展示气泡：

> 我还是不明白。我觉得我的需求没问题啊，我发消息，先立刻显示已经发出去了。这和等不等其他部分有什么联系吗？

场景4：历史批次加载过程中服务器产生新的助手回复。

> 不能等加载完了，再出现助手的回复吗？你明白我意思吗？有没有需要我再澄清的？

场景5：原第20条在前10条加载期间有新消息。助手提出固定当前10条、该变化进入下一批、发布后按最新活动时间排序，用户答：

> 可以。还有吗？现在有没有过于复杂的特殊场景？有的话考虑降级成普通场景

用户最后明确整个对话的范围：

> 记住，我说的对话，不只是消息，还有状态，消息列表状态，标题，上次配置，压缩情况，等等等所有的和这个对话有关系的内容哈，不要我点开一个对话，每个部分各变各的，各自更新，就很乱。

有效决定（依据以上原话归纳，不是原文）：

- 先展示缓存，最近更新10条对话优先成批加载、一起发布；其余变化下一批读取后一起发布，不逐条发布。
- 对话包含消息、运行/列表状态、标题、上次模型及配置/思考强度、压缩情况等所有关联显示；任何新加对话字段也须遵循共同更新，不得只统一消息正文。
- 打开某条对话不绕过批次；加载中新增助手回复/状态不得直接穿透显示。当前批次范围固定，后续变化进入下一批，不不断重新计时。
- 超时结束本批，成功部分一起发布；超时对话保留已有缓存、显示错误并记录对话ID及失败原因。具体超时时长尚未确定，不把某个秒数写成用户决定。
- 用户发送气泡立即显示，历史合并不能丢失或重复它；沿用消息顺序、列表活动时间排序，不另加发送成功置顶机制。此本地操作反馈不授权其他关联字段各自更新。
- 待后续考虑而非当前实现：点开的对话独立优先发布（场景2的B）。
- 验收必须观察整个对话各处的时间线，不能只用正文出现或最终截图证明同步。需求已确认不等于当前代码已实现。

关联文件：ui-feishu/src/usePageSnapshot.ts、ui-feishu/src/FeishuApp.tsx、ui-feishu/shared/features/conversations/state/conversationMerge.ts、hooks/useConversationSession.ts、hooks/useConversationCatalog.ts（后两者位于同一conversations目录）、ui-feishu/shared/features/project-directory/hooks/useProjectDirectory.ts、ui-feishu/shared/features/models/components/ChannelManager.tsx。

验收场景：带缓存刷新、连续追加含图片消息、切换对话、状态与最后消息更新、慢请求与失败保留现有内容。检查页面时间线而非只看最终截图。滚动保护仍按根 AGENTS.md 执行。

## 具体内容

使用场景：用户离开电脑后，通过手机或浏览器继续查看和控制一个项目中的 Codex 对话。

当前体验：已有真实会话、发送、停止和过程展示；跨设备终态和流式交接仍需真实长任务验证。会话切换定位修复已完成源码修改，尚未运行态验收。

交互变化：保留事件重连、权威状态、会话补拉和当前模型/上下文设置；切换会话返回时优先恢复到之前看到的消息锚点。
