# 用户原话与澄清的持续维护

## 用户原话

来源：本次 Negus 维护对话，2026-10-30 当前发言；未取得消息级标识。

> 麻烦你更新维护一下，让每个negus助手，以及想修改negus的其他来源的助手都用起来吧。并且你可以提意见怎么简化高效。我唯一的需求就是，用户的原话要被记录好，不要反复来回冲突。现在经常是，助手误解了我的需求，我澄清后，做对了，但是下一次另一个助手，没有找我澄清又按回它的错误理解修改了。

本次对话此前原话（具体发言日期未独立核实，记录于2026-10-30）：

> 有没有一个需求列表，我们没次改相关文件都写下记录那种？比如说，我提了一个需求，但是助手发现我之前针对相关文件，有完全相反的描述。然后就和我确认之类的。

> 其实以前negus好像就有这个功能但是一直没怎么利用好。

## 当前有效决定

- 保存用户原文及后续纠正，防止其他助手重新采用被纠正的理解；有效性与功能是否已完成分开。
- 复用现有项目管理条目，不增加第二套需求系统。具体工作步骤统一放在根目录 AI_ASSISTANT_WORK_RULES.md，其他入口引用。
- 只有未被当前用户明确替代的真实冲突才询问；已澄清的要求不反复提问。
- 助手实现建议不是用户原话或已确认产品决定。发言日期不明时记录收录日期，不倒推日期。

## 相关入口与验收

- 外部仓库助手：AGENTS.md → INDEX.md → 相关 item.md。
- Negus 普通对话及员工：共用 maintenance-instructions.mjs → 安装目录 AGENTS.md；不复制到每个员工提示词。
- 验收：普通与员工实际提示词组装均包含需求入口；索引可定位条目；澄清和开放问题分开；历史原话保留。
- 这是维护流程约束，不是强制拦截所有外部工具的权限系统；无法保证不读取仓库规则的外部程序遵守，不宣称所有现存对话已刷新提示词。
