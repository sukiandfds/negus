# 项目记忆入口与可解释上下文边界

## 用户原话

原始对话未保存在本条目中，待从原始对话补录；不根据功能文档反推用户原话。

## 简短摘要

项目管理页提供“项目记忆”区域，可以查看最近更新、产品决策和公共群聊完整历史，并明确 Agent 实际接收的上下文范围。

## 具体内容

页面复用现有项目管理文档和群聊读取接口，不建立第二份记忆数据库；用户点击“读取完整历史”时按服务端分页读取目标项目公共群聊。员工私聊不进入该历史，摘要不作为事实，完整历史不会隐式注入模型上下文。

## 预计效果

用户能从一个入口理解项目最近发生了什么、哪些记录会被 Agent 看到，并按需读取完整群聊历史。

## 当前状态

入口和读取逻辑代码已存在，构建记录通过；真实浏览器、手机和公网群聊历史点击仍待验收。

### 2026-11-22 对话提示词与可变上下文

用户原话：「请你把旧的混乱浪费结构都删除。然后引入新的结构。依然是尽量多复用，就是把对应结构提取出来复用。然后后面我们再根据群里和员工来增加对应需要功能的提示词。」

普通、员工、群聊、后台共用固定规则、工具说明和上下文更新入口。仅前台加载前台派工职责；保留已有岗位规则。本轮不新增角色功能。用户画像、当前模型、员工补充上下文只在首次使用或变化时交给模型；原生压缩后重新提供当前版本。历史记录、Codex 原生请求和压缩继续使用原有实现，不引入第二套运行时。

### 2026-11-22 提示词命名及普通对话的组成（替代上文前台派工职责）

用户原话：「以后这个部分叫做negus的系统提示词。定义就是在negus中发起的对话都会有这段提示词。然后是negus工具提示词，指的是negus系统中，所有的对话可以调用的工具。然后你说的前台提示词我完全看不懂你说的，直接删了。」

固定提示词顺序：Negus 系统提示词 → Negus 工具提示词。普通对话到此为止。员工、群聊和后台沿用同一个入口；已有专属职责由相应入口追加。删除前台提示词及选择它的开关。用户偏好仍单独作为可变上下文提供。

2026-11-22 用户原话：「普通对话，员工助手，员工助手在群聊中，都要按照这个方式来合理调用工具和技能。」「技能目录中，对应技能的具体路径，应该是可变路径。」
有效决定：三类对话共用系统提示词和工具目录；面板与助手引用同一清单，工具详情按需读取。条目相对于目录文件定位，迁移安装位置无需改盘符。请求用户选择属于工具，沿用会话实际提供的交互能力。

2026-11-23 用户原话：「写入我们negus的系统提示词中。不用太复杂，限定太多，指明路径规则即可」「要求不显示真实敏感信息即可」。系统提示词定义普通对话收到草稿路径后的按需更新规则；话题与主线按当前对话传入，未变的参考内容不重复注入。
