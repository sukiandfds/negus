# FEAT-022：共享供应商配置的 Node 修复

日期：2026-09-30。状态：handoff_pending。基线：c8c7b66d686fb3a896c4c939fe6dec9bb2d8d8d4；分支 codex/publish-current-panel。保留此前工作区改动，未提交。

## 用户目标与本轮保护

用户先用 Negus 配置供应商，以后安装 CC Switch 后可读取同一份配置，不需要导入、不要求先安装 CC Switch 或 Python。双方当前选择仍独立。

本轮原话：“请你小心修复。一定不要弄得最后，我连现在的negus都用不了了”。

本轮不重启正式后端、不覆盖线上前端、不改真实供应商数据库、Key 或当前 Codex live 配置。修复代码完成不等于线上已生效。

## 修复内容

- 用 Node 内置 SQLite 替换 Python 子进程。运行环境需提供 node:sqlite 和 backup（Node 22.16+；本机验证为 24.19.0）；按需加载，旧环境缺少能力时仅配置操作明确报错，不导致服务模块加载失败。
- 只读浏览不存在的数据库返回空列表，不创建文件。首次保存 API Key 配置时，在默认 ~/.cc-switch/cc-switch.db 原子创建兼容 providers 表；已有数据库不重建、不自动迁移、不修改 user_version。
- 新库保留 user_version=0，由 CC Switch 自身初始化其余表并进行迁移。依据安装版本 3.20.4 官方源码核对；尚未进行全新用户下的 CC Switch 图形界面首次启动验收。兼容性不可扩展为对任意未来版本的保证。
- 发现旧 config.json、未知结构或高于已核对版本19的数据库时保护原文件；旧 JSON 迁移未在本轮实现。现有 CC Switch 自定义数据目录尚未自动发现，默认目录外的配置仍需后续适配。
- 保存和删除使用事务、最新行比较、写前完整数据库备份，保留其他应用条目与未知字段；删除开启外键级联。新库、备份文件权限0600。备份位于共享目录 backups/negus-*.db。
- 共享供应商不再复制 Key 到 DPAPI。Node 命令认证直接读取同一份共享数据库，生成的运行配置、进程参数和错误信息不含 Key。共享库沿用 CC Switch 原本的明文存储格式，不宣称加密。
- 运行配置带配置指纹；其他工具改动后，旧运行环境拒绝把新的 Key 用于旧的地址，需在任务结束后重新加载。已有 Windows 非共享供应商 DPAPI 链路保留，本轮不迁移历史 Grok 私有凭据。
- 共享供应商刷新直接使用其共享地址与 Key 请求 HTTPS /models，目录仍是 Negus 本地派生缓存，不擅自改供应商默认模型。当前原生 Codex 模型目录继续由原生 model/list 提供，刷新不再被无关的共享配置读取失败卡住。
- 前端 GET 请求优先显示后端的具体错误，不再将配置错误全部遮蔽成通用503。没有新增弹窗或配置入口。
- 当前被 CC Switch 启用的配置仍禁止编辑/删除，防止数据库与 Codex live 配置分离；新增与非当前配置可独立管理。解除这项保护需要另行处理 live 文件一致性，不在本轮冒险修改。
