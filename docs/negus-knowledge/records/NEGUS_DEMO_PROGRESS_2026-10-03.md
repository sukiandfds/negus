## 三、已经做了什么

### 1. 检查并修复 Negus 的 Codex 运行入口

- 发现正式服务的模型接口曾返回 503，原因是程序只识别旧版应用内的 Codex 路径。
- 补充新版 `ChatGPT.app / CodexCLI.app` 路径发现，保留既有路径兼容。
- 修复已通过发布流程加载，正式服务模型接口恢复可用。

### 2. 检查会话权限与模型渠道隔离

- 发现普通项目会话可能继承只读权限，影响用户授权的电脑与开发操作。
- 调整普通项目会话启动、恢复与分叉的权限传递；显式配置的权限仍需按配置处理。
- 处理新建空会话尚未持久化时不适合直接恢复的问题。
- 发现独立模型渠道使用独立 `CODEX_HOME`，因此不会自然获得主机已有的电脑工具配置。

这些调整涉及权限语义，相关自动化测试通过，但不能把测试通过等同于所有历史会话和渠道均已实际验收。

### 3. 接入并验证电脑工具

- 增加 Negus 电脑 MCP 工具及本机组件，提供权限检查、截图、打开网页、点击、输入、按键、滚动和公开网页读取。
- 用户已经完成辅助功能和屏幕录制授权；通过正确的 macOS 应用启动身份检查，两项权限均为 `true`。
- 发现发布快照中工具误报“未安装”：MCP 子进程没有继承安装目录环境变量。
- 改为在 MCP 配置中显式传入安装目录，修复已上线。
- 正式 Negus 会话已实际完成权限检查、`1920×1080` 截图及 GitHub API 读取。

随后补做真实点击输入验收，发现自建输入工具返回成功，但浏览器输入框没有收到文字，因此电脑操控整体验收失败。

### 4. 改用已有原生能力进行验证

- 使用本机已安装的原生电脑工具，在独立本地测试页面输入 `NATIVE-CHECK-48216` 并点击验证按钮。
- 页面显示 `收到：NATIVE-CHECK-48216`，测试服务记录了对应值及真实点击事件。
- 这证明本机原生工具可以完成操作，**不证明正式 Negus 已经打通相同链路**。
- 已修改 Negus 的启动配置，使独立模型渠道能复用主机已配置的原生 `node_repl` 电脑工具；不复制模型供应商认证配置，不打包分发原生工具程序。
- 最新相关测试共 28 项通过。该原生接入修改尚未发布。
- 独立渠道实测已发现工具、列出应用并读取 Chrome 状态，但仍有参数形式、状态树读取和键名错误，尚未取得目标输入回执。

### 5. 验证 GitHub 与 Cloudflare

- GitHub：正式 Negus 会话通过工具读取公开仓库 API，返回 HTTP 200。
- GitHub 网页：直连曾超时；显式使用现有本地代理访问返回 HTTP 200。
- GitHub 推送：HTTPS dry-run 因缺少用户名凭据失败。现有 SSH 部署密钥尚未完成可用性验收，不能承诺推送可用；未执行实际推送。
- Cloudflare：现有命令行认证可用，成功查询隧道；当前使用的隧道有 4 条连接。
- Cloudflare 控制台：命令行访问曾得到 403 人机验证挑战，经代理访问也出现 TLS 超时；尚未证明浏览器控制台登录和操作正常。

### 6. 核对锁屏与后台运行

- Mac 当前接电配置为 `sleep=0`，显示器休眠为 10 分钟。
- 自动锁屏、显示器休眠和整机睡眠是不同状态。
- 自建截图工具在锁屏时曾超时，现有工具增加了明确的锁屏错误提示。
- 该提示只是错误处理，**不是锁屏后台持续执行或解锁后恢复能力的实现证明**。
- 最新工具指令已明确：后台联网、文件处理和代码执行不应被统一要求等待解锁。
- 尚未完成“实际任务开始 → 自动锁屏 → 后台继续执行 → 结果可见”的完整验证。

## 四、遇到的问题与判断纠正

| 问题 | 影响 | 当前处理或结论 |
| --- | --- | --- |
| Codex 应用内路径变化 | 正式模型接口 503 | 已修复并上线 |
| 会话权限和渠道环境不一致 | 部分会话缺少操作权限或工具 | 已调整部分权限传递；原生工具复用仍在验证 |
| MCP 安装目录未传入子进程 | 发布后电脑组件误报未安装 | 显式传递安装目录，正式会话已验证 |
| macOS 权限与启动身份相关 | 直接运行二进制与应用启动的权限结果不同 | 已按应用身份启动检查，用户已完成系统授权 |
| 自建工具输入“假成功” | 工具返回成功但用户页面无变化 | 已用真实页面发现，不能作为可用能力交付 |
| 原生工具在不同调用环境中的参数差异 | 独立渠道调用失败或无法完成操作 | 正在验证；尚未发布 |
| GitHub 直连与代理结果不同 | 容易被误判成整机断网 | 已分别验证 API、直连和代理访问 |
| Cloudflare 403 挑战 | 不能通过普通 HTTP 请求证明控制台可用 | 隧道认证有效；控制台仍待浏览器验收 |
| GitHub 推送认证未通过 | 无法承诺演示发布代码 | 保留为独立未通过项 |
| 锁屏后截图超时 | 桌面操作与后台任务容易混淆 | 不再把解锁作为所有后台工作的前提；跨锁屏任务仍未验收 |

过程中有三点需要明确纠正：

1. **过早实现了自建桌面组件。** 后续证据表明原生工具可以完成输入点击，应优先复用并验证现有能力。这条绕路增加了工作量，现有自建输入路径仍不可靠。
2. **曾把“需解锁才能验证桌面截图”表达成继续工作的统一前提。** 这不符合用户的后台运行要求，已纠正。
3. **曾因 `lsof` 查询无输出而判断代理端口没有监听。** 后续实际代理请求返回 200，`netstat` 也显示监听。先前证据不足，不能将“代理未启动”作为已确认根因；本次未据此切换系统网络。

此外，早前测试页出现过 `123`，无法证明由助手输入，未将其计入自动操作成功证据。
