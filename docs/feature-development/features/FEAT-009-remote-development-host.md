# FEAT-009：原开发电脑远程运行、开发与应急恢复

## 当前快照（2026-09-30）

用户最新要求覆盖此前“不提前加入自动恢复”的范围限制。Mac 已提供独立检查/恢复、前端构建发布、后端安全重启脚本和用户级定时检查。正式后端仍运行旧版本，首次加载和安全收口的正式体验待验证；功能保持 handoff_pending。

具体命令、恢复条件、日志、首次加载与验证统一见 [维护说明](../../operations/NEGUS_SERVICE_CONTROL.md)。没有新增页面或模型定时调用，不影响已有文档整理。

## 2026-07-28 历史快照

以下计划、限制与验证属于当时 Windows 范围；有冲突时以上述最新确认和维护说明为准，不将旧“下一步”当作当前指令。

- 项目代码、Codex 环境和实际服务继续留在原开发电脑；当前电脑和手机只通过 Web 远程使用。
- 用户在原电脑前时仍正常使用 Codex Desktop，Web 只是远程补充。
- `9360` 当前由 `start-web-demo.ps1` 启动，没有远程启动或重启接口。电脑一般不会频繁重启，但项目进程可能被关闭。
- `9360` 停止后，现有网页也随之不可用，无法在同一页面点击启动。
- 当前可用兜底是回到原电脑处理，或使用向日葵等远程桌面工具。
- 普通代码修改、项目依赖、测试、构建和 Git 通常可在普通用户权限下完成；真实 Windows UAC 一旦出现，网页无法操作安全桌面。
- 已提供完全只读的普通用户开发环境检查器，检查项目/用户目录 ACL、Node、pnpm、Git、PowerShell、端口和常见 UAC 风险；它不安装、不修复、不启停进程，也不触发提权。

## 用户实际需要

1. 原开发电脑持续承担开发和运行，当前电脑不迁移项目，也不重复搭建开发环境。
2. 用户从 Web 提需求后，原电脑上的 Codex 修改代码、测试并完成必要更新；Web 持续显示 Codex 原有过程和最终结果。
3. 文件修改、测试和构建通知属于 `FEAT-001` 的 Codex 过程同步，不再单独设计“正在修改”功能。
4. 项目进程被关闭时，优先考虑网页中的最小“启动项目”紧急按钮或其他远程启动方式；如果无法保证该入口独立存活，向日葵是可接受的兜底。
5. 正常开发尽量像 OpenClaw 一样在用户权限和项目目录内完成，不触发 UAC，也不让用户处理权限细节。
6. 只有驱动、系统服务、系统安全策略等真正需要管理员权限的工作，才作为少量本机维护事项单独报告。

## 当前已确认的实际行为

| 场景 | 当前行为 | 当前结论 |
| --- | --- | --- |
| Web 提出普通代码需求 | 原电脑上的 Codex 可以修改仓库并执行命令 | 已具备基础能力，但过程同步仍有 1–2 分钟后停更的问题，见 `FEAT-001-I08` |
| 修改前端并重新构建 | `web-ui/dist` 更新后，服务会在后续请求读取新静态文件 | 浏览器可能需要刷新；不应额外发明复杂发布流程 |
| 修改后端 `.mjs` | 运行中的 Node 进程不会自动加载新模块 | 确实需要重启项目进程，但只在后端变化时处理 |
| `9360` 被关闭 | 当前网页和 API 一起消失 | 如果要保留网页紧急按钮，必须存在一个独立于 `9360` 的最小入口；是否值得做需结合实现成本确认 |
| 电脑重启 | 尚无已验证的自动恢复 | 用户认为不是常见场景，当前不列为优先需求 |
| 出现真实 UAC | 普通网页和远程自动化不能操作安全桌面 | 正常流程应避免触发；必要时使用本机或向日葵维护，不设计远程点击 UAC |

## 无 UAC 的正常开发方式

目标不是提前拒绝开发，而是自动选择不需要管理员权限的实现路径：

- 项目、Node、pnpm、Git、Codex 和缓存放在当前用户可写目录；
- 依赖优先安装到项目目录或用户目录，不默认使用全局管理员安装；
- 修改、测试、构建、Git 和项目进程启动都使用普通用户权限；
- 一个命令可能触发提权时，先尝试项目级、用户级或 WSL2 等等价做法；
- 只有确实不存在普通用户替代方案时，才暂停该系统级步骤并告诉用户需要一次本机维护；
- Codex 内部命令审批与 Windows UAC 是两件事，不能混在同一个“批准”流程中。

OpenClaw 式体验的关键不是绕过 UAC，而是把运行环境、依赖和权限提前放在用户可控范围内，使绝大多数日常工作根本不会走到 UAC。

## 最小更新体验

```text
用户在 Web 提需求
  -> Codex 按原有过程事件显示分析、命令、文件修改和测试
  -> 前端有变化：完成构建，Web 刷新或提示加载新版本
  -> 后端有变化：只在需要时重启项目进程，Web 自动重连
  -> 显示最终结果或明确失败原因
```

正常成功路径不展示额外部署面板、双 Worker、自动回滚或复杂阶段。只有项目进程确实退出或更新失败时，才显示应急操作。

## 目标与边界

当前计划包括：

- 原开发电脑继续作为唯一开发与运行主机；
- 用户权限下完成正常开发；
- 必要时提供最小项目状态和启动入口；
- Web 在更新后恢复连接并加载新页面；
- 向日葵等远程桌面作为极端情况下的可接受兜底。

当前不提前加入：

- 电脑重启后的完整无人值守恢复；
- 大型 Supervisor、双 Worker、蓝绿发布和自动回滚；
- 公网管理员 Shell；
- 自动点击、绕过或远程操作 Windows UAC；
- 所有后端代码都无重启热更新；
- 为文件修改另建一套独立状态系统。
