# FEAT-021 项目记忆入口与可解释上下文边界

## 修改前体验

项目管理页分别展示计划、进行中条目和最近更新，但没有一个明确的“项目记忆”入口；用户需要切换到群聊页才能读取公共记录，也看不到哪些记录会进入 Agent 上下文。

## 当前定义与用户可见变化

- 项目管理页增加“项目记忆”区域，读取同一份项目管理文档中的最近更新和“产品决策”条目；点击条目仍进入原有详情面板。
- “读取完整历史”按现有 `/api/group/rooms` 和 `/api/group/messages` 的服务端分页读取目标项目公共群聊，按序号排序、去重后在侧栏显示；“打开群聊界面”继续使用真实群聊入口。
- 页面明确说明：群聊 Agent 默认接收自上次处理后的新增消息，并受消息数和字符数限制；项目经理入口当前只带入项目 ID、名称、阶段和目标。完整历史不会隐式注入，早期内容需用户从入口按需读取。

## 数据归属与边界

- 最近更新和关键决策来自 `docs/project-management` 的既有解析结果，不复制或生成第二份记忆数据库。
- 群聊历史来自工作项目公共群聊 API；不读取员工私聊，不把摘要当作事实，不改变 Agent 会话归属。
- 本功能是显式读取入口和上下文说明，不引入隐式长期记忆、自动摘要写回或跨项目数据共享。

## 验证

- `pnpm build:ui`：通过（TypeScript 检查和 Vite 生产构建）。
- `git diff --check`：待本轮收口执行。
- 未启动常驻服务，未完成真实浏览器、手机和公网群聊历史点击验收。

## 回滚

移除 `ProjectMemoryPanel` 的挂载及对应样式即可；不影响现有项目管理数据 API、群聊历史存储和 Agent 上下文流程。
