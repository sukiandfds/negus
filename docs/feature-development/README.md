# 功能档案维护

更新时间：2026-09-29 18:31 +08:00；PM-003。

先从 [功能索引](FEATURE_STATUS_INDEX.md) 找到相关 FEAT，再按需读源码与证据。产品方向见 [总定义](../../PRODUCT_DEFINITION.md)，工作规则见 [助手规则](../../AI_ASSISTANT_WORK_RULES.md)，历史利用见 [文档导航](../README.md)。

## 职责

- FEAT 档案：功能行为、边界、当前实现、问题和验证的详细来源。
- 功能索引：简短摘要与定位；不保存完整需求表、修复流水或独立开发排期。
- 项目管理 item.md：当前工作摘要与状态；updates.md：简短变化及证据链接。
- research/、records/：研究、事故、原话和长篇历史证据。
- DEVELOPMENT_COMMON_MISTAKES.md：能跨功能复用的经验。

产品行为改变时同步总定义；只有实现或验证变化时更新相关档案和必要摘要。不要在这些位置复制同一份完整正文。

## 档案内容

1. 编号、标题、状态、版本、更新时间、关键代码路径。
2. 当前有效行为与边界，明确哪些是产品目标、哪些已实现。
3. 架构与数据来源，仅记录核对过的事实。
4. 仍有效的开放问题和后续工作；旧方案标记被替代，不继续当成待办。
5. 日期化变化与验证证据；大篇幅内容回链独立记录。

现存档案的字段名有历史差异。没有读取依赖核对前不批量改字段；元数据与正文冲突须明确说明。功能版本不是整个产品版本。

## 问题与验证

功能专属问题使用 FEAT-xxx-Ixx；普适经验使用 PROC-xxx。写清现象、根因证据或待验证点、正确处理方式及来源；避免多个文件重复事故全文。

区分实现、提交、部署、自动化测试、真实浏览器/供应商和用户验收。历史“未提交”“未重启”只代表记录当时，先核对 Git 和运行状态再用于当前交接。

每次功能变化仍更新对应档案；时间线保留原始记录，不重写历史让错误看起来未发生。不新增没有独立内容的日志文件。
